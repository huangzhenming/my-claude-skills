# 辐射式原理图布局

## 模型（用户 2026-09-28 定）

> 「同一层不是上下关系，而是**圆形关系**。以主 SOC **正上方的引脚为 0°**，
>   其它同层按照和圆心的**连接网络顺序**排开。」

**为什么它不是启发式**：芯片引脚绕本体的角序是**符号固定的**。
只要卫星的环向次序 == 它们所连引脚的角序，**辐条之间就不可能相交** ——
交叉只出现在「环序 ≠ 引脚序」的地方。

配套第二条（同样是用户提的）：**电源/地网不参与层级**。
不排除的话 GND 连着十几个器件，BFS 一跳就把全图铺平、层级全糊。
只靠电源网相连的器件（去耦电容）层级最低，单独放内圈贴着电源脚。

## ★ 先诊断，再决定用不用 —— 这条最重要

定义一个可读的判据：**每个卫星的方位 vs 它所连圆心引脚的方位，偏差 >45° 的比例**。

daikin-rcu 四页实测，以及落地后的真实交叉数：

| 页 | 偏差 >45° | 交叉（原布局） | 交叉（辐射布局） | 结论 |
|---|---|---|---|---|
| P3 | **11/15** | 17 | **5** | ✓ 修好了 |
| P2 | 10/19 | **3** | 13 | ✗ 变差 |
| P1 | **4/25** | **22** | 33 | ✗ 变差 |
| P4 | 2/5（人手工摆的） | **24** | 33 | ✗ 变差 |

→ **辐射布局是修复工具，不是默认布局。**
只有当诊断显示布局**严重非辐射**（本工程的经验线：偏差 >45° 的超过一半）时才值得推倒重排；
布局本来就接近辐射的，推倒重排只会把器件挤到环上、逼出更多绕行
（P1 的导线段数 113 → 133）。

⚠ **而且诊断只是必要条件，不是充分条件**：P2 有 10/19 偏差却仍然变差。
**最终判据只能是落地后的交叉数**。

## 流程（缺一步就白跑）

```
① 量交叉（改前）
② radial --plan   看诊断和新坐标
③ **先把当前 layout/*.json 另存**      ← 我漏了这步，直接覆盖，差点回不去
④ radial --apply  只动器件位置和摆向
⑤ build_page --snapshot                ← 漏了这步，place() 会按旧快照把器件全搬回去
⑥ build_page --apply --rewire          器件动过，快照里的导线全是旧坐标
⑦ 量交叉 + 导网表；**没变好就回退**
```

## 实现上的三个坑

### 1. 环形约束不能用「逐对推开」的松弛

角度是模 360 的。某一项被推过邻居之后 `(b−a) % 360` 反而变成一个很大的正数，
看起来「间隔够了」，**于是顺序悄悄反了** —— 而保持环序正是这套方法的全部意义。
实测 5 个点里有两对只隔 7° 和 14°。

→ 正确做法：**在最大空隙处剪开环 → 展成直线 → 按序做最小间隔投影 → 合回去**。
  只许往后推，保证严格递增，环序不变。

### 2. 环半径必须避开圆心器件的本体

不算净空的话卫星直接落在芯片里面（P3 的 ESP32 模组 290 高，15 个卫星全叠上去）。

### 3. 环有**容量**：周长 / 最小间距

超了的话撑开算法只能退化成均分，弧长掉到最小间距以下 —— 器件挨太近，
路由**一条干净路径都找不到**、符号也放不下，**网表当场断**。
实测 P1 有 20 个一级卫星挤一个环，均分只剩 18°、弧长 60（<90），
`AIO_BUS` / `BR_N` / `VCC5` 三条网断掉。

→ 先尽量撑大环（受可用区限制），还装不下就**隔一个往外挪一圈**，两个子环各自保持角序。

## 其它

- **图框取不到**：它不是图元，`getDocumentSource()` 里只有 `CANVAS` 原点。
  可用区只能量「现有图元的并集包围盒」。
- **用椭圆不用正圆**：图纸是横的，正圆要么浪费左右、要么上下出界。
  环序才是本质，压成椭圆完全不影响它。
- **圆心器件相对图纸越大，模型越退化成分列**：P3 的 U3 本体 290 高、
  可用区只有 500 高，竖直净空要 235 而半轴只有 190 —— 环只能压扁成左右两列。
  这其实正是人画 ESP32 原理图的样子。
