# 元器件选型与校验

**选型和校验是两件事，都要做。** 选型决定能不能买到、贵不贵；
校验决定图上这颗是不是真的对（封装、3D 模型、引脚方位）。
历史上出问题的多数是**校验**这一步跳过了。

---

## S1. 优先选立创商城「量大、便宜、现货」的料

**场景**：任何新放器件
**机理**：后期做元器件标准化（归并料号、换料、重画封装）的代价远高于选型时多花一分钟。
停产件、库存个位数的件、冷门品牌件，都会在打样或第二批时变成返工。
**代价**：daikin-rcu 原方案选了 MS1192，建器件时才发现立创库里标着**「停产」**，
余货 252 片，且**无引脚兼容替代**（MAX22088 库存 4 片、贵 7 倍、封装不同）。
**出处**：daikin-rcu（用户提出并确认）
**失效条件**：用户手上已有存货的器件（本项目的 ESP32 模组、CH340N）按现有的来，不另选。

### 判据（按优先级）

1. **在产**（器件库名称里带「停产」的直接排除）
2. **现货充足** —— 至少是需求量的 100 倍。库存 < 1000 的要当心
3. **JLCPCB Basic Part 优先**（如果要贴片），Extended 次之
4. **价格** —— 同等条件下选便宜的，但**不要为省几毛钱选冷门品牌的关键器件**

### 反直觉的一条：正品有时比国产 clone 还便宜

daikin-rcu 选 Buck 时：MP2315 原厂 ¥14 / 国产 clone ¥2.28，
而 **TI 的 TPS54202DDCR 只要 ¥1.06、库存 15 万、参数还更合适**（4.5~28V 覆盖更宽）。
→ **别默认「原厂=贵」，多搜两个型号。**

### 工具

商城接口**必须从 EDA 客户端内部 fetch**（沙箱里直接打是 403）：

```
POST https://pro.lceda.cn/api/eda/product/search
     body {keyword, page, pageSize}
     → result.productList[]：code / model / brandName / standard /
       stockNumber / priceList[] 阶梯价 / "JLCPCB Part Class" / pdfFileUrl
⚠ 搜索结果里的 productParams 是 null，参数要另外用 lib_Device.getByLcscIds() 取
```

`pdfFileUrl` 拼 `https://atta.szlcsc.com` 就能拿到规格书（同样从客户端内 fetch）。

### ⚠ 电阻电容：每个阻值必须有自己的料号

daikin-rcu 第一版脚本里**所有电阻都填了同一个料号**（一颗 33kΩ）。
原理图上显示的值是对的，**但 BOM 导出来会全变成 33k**，四块板全废。

→ 批量放无源件时，**逐个阻值查料号**，并在脚本里加一道校验：
「每个显示值 ↔ 一个料号」必须一一对应。

⚠ 厚声的 `0603WAF470KT5E` 这类编码**分不清 4.7Ω 还是 47Ω**，
优先选 FOJAN 的 `FRC0603F4R70TS`（`4R70` 无歧义）。
⚠ 查到的料号要看库存：`0603WAF1002T5E`（10k 1%）**库存是 0**。

## S2. 放进图之前必须校验器件本身

**场景**：从库里选到一个料号、准备放进原理图之前
**机理**：库里有这个料号 ≠ 它的符号/封装/3D 模型是对的、是有的。
**代价**：
- canmv_serdes：94 个器件**一个真 3D 模型都没有**（13 个专业版 uuid 全部 403，27 个连引用都没有），
  编辑器画的全是占位方块，到 3D 预览时才发现
- daikin-rcu：CA-IF42088 **立创库里根本没有符号和封装**（`hasDevice` 为空），
  必须自建；库里找到的 QFN-24 母版封装 EP 是 2.5mm 而手册推荐 2.60mm
**出处**：canmv_serdes（3D 模型，首次）；daikin-rcu（符号/封装缺失，二次）
**失效条件**：无。每颗新器件都要过。

### 校验清单

| 项 | 怎么查 | 出问题的信号 |
|---|---|---|
| **器件存在** | `lib_Device.getByLcscIds("C…")` | 回 `[]` → 库里没有，要自建符号+封装 |
| **停产** | 看 `otherProperty["LCSC Part Name"]` | 字符串里带「停产」 |
| **封装尺寸** | 看封装**名字**里编码的尺寸 | ⚠ `lib_Footprint.get()` **不回焊盘几何**，只能从名字读 |
| **3D 模型** | `GET https://modules.lceda.cn/3dmodel/<uuid>` | **403 = 下不来**。这是判据，不用猜 |
| **引脚方位** | 只能在 **PCB 上读焊盘世界坐标**验证 | 名字里的 `TL`/`BL` 不可靠，必须实测 |

### 3D 模型的两条硬事实

1. **专业版系统库的模型对外不开放**（GET 回 403，263 字节 AccessDenied）。
   能下载的是**标准版**的对象，uuid 藏在标准版封装 dataStr 的 SVGNODE 里：
   ```
   GET https://easyeda.com/api/products/<C号>/components?version=6.4.19.5
   → result.packageDetail.dataStr.shape[] 里那条 "SVGNODE~{…}" 的 attrs.uuid
   ```
2. **判客户端的状态要从客户端里发请求。** 在客户端外用匿名 Python 打接口拿到 401/403，
   **不代表客户端取不到**（ML307H 项目据此误判成「没登录」，白查一轮）。

⚠ 确实没有模型的器件要**如实报告**，不要拿相近封装硬凑。

### 封装引脚方位：唯一可靠的验证办法

封装名里的 `TL` / `BL` 指引脚 1 角的位置约定，**但不同库的约定不一致**。
唯一可靠的验证是在 PCB 上用 `pcb_PrimitiveComponent.getAllPinsByPrimitiveId()`
读**焊盘世界坐标**，和手册顶视图对。

⚠ 这个方法名容易记错：**是 `getAllPinsByPrimitiveId`，不是 `getAllPadsByPrimitiveId`**
（后者不存在）。

## S3. 同一颗料号的显示值要和实际值一致

放器件时同时设 `designator` 和显示值，**放完读回核对**：
位号集合必须与计划完全一致（`lib/gridcheck.py` 的 `check_designators()`）。

导 BOM 之后还要再核一遍 **料号 ↔ 值** 的映射，这是最后一道防线。
