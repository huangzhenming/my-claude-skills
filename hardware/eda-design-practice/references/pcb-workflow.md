# PCB 四步法（人机分工契约）

```
① AI 估面积      器件数 + 裸面积 + 经验密度系数 → 建议板框尺寸
② 人定板框 + lock 关键器件        ★ 交接点
③ AI 自动布局    重力/气泡求解 → 区域夹取 → 贪心格点合法化 → 预览
④ 人布线                          （未来可扩展交互式自动布线）
```

★ **② 之后 AI 不越界。** 板框和锁定件是人的决定，AI 只在给定边界内求解。
AI 提出的板框只是**建议**，不能自己画上去。

---

## ① 估面积

输入：器件清单 + 每个的封装外形尺寸。
输出：**待布器件裸面积** 和 **建议板框**。

密度参考（实测）：

| 项目 | 裸面积 / 可用区域 | 难度 |
|---|---|---|
| canmv_serdes 发送板 | 21% | 宽松 |
| canmv_serdes 接收板 | **53%** | 紧，要精心排 |

⚠ 用 `Footprint.extent()` 拿到的只是 **(宽,高)**，而多数封装**偏心**
（SMA 座的喇叭口伸到板外、电感的外形中心比原点低 2mm）。
必须自己算**偏心包围盒**（外形 ∪ 焊盘），否则障碍物位置会差好几毫米。

---

## ② 人定板框 + lock

交接物：板框尺寸 + 已锁定器件的位置和旋转。

⚠ **板框不是 `pcb_PrimitiveLine`**，是一条 `polyType:"BOARD_OUTLINE"` 的 `POLY` 记录
（`path:["R",x0,y0,x1,y1,0,圆角]`），只能从 `getDocumentSource()` 里解；
`pcb_Primitive.getPrimitiveBoardLine()` 实测恒返回 null。

### 标定旋转约定（每块板做一次）

用**已锁定的器件**标定，别猜：

```
rot=0    焊盘世界偏移 ≡ 封装本地坐标
rot=−90  焊盘世界偏移 (dx,dy) = (ly, −lx)
⇒ API 的 rotation = y 向上系里的标准逆时针
```

坐标：板坐标 **mm、y 向上**，PCB API 是 mil，只需 `/0.0254`，**不翻 y**
（和原理图不同，原理图要翻）。

## ③ AI 自动布局

### 重力模型要**按块用，不按整板用**

`solve()` 产出的是「挂在山峰下的树」——重力把所有件往一个方向拽，
整板跑出来又高又窄、不铺板面；而且它**结构上不认识板框和禁布区**。

正确用法：

- **块内**谁挂哪边、朝哪个方向 → 交给重力求解（hub 用 `fixed`+`angles` 钉在板坐标上，
  解出来直接是板坐标，`g=0` 免得外围件全堆一侧）
- **块间**怎么摆、关键链路（如 Figure 30 那种手册指定的链序）→ **显式定死**，写成数据

### 已知陷阱

| 陷阱 | 说明 |
|---|---|
| **电源网识别** | 库自带的 `is_power()` 大小写敏感，`3V3`/`1V8_A`/`1V0`/`VIN_CAM` 一个都不中。不扩的话去耦电容会被拽向全网重心而不是就近贴电源脚 |
| **弱不动点迭代** | 「夹回区域 ↔ separate」区域一满就来回拉锯。必须加一道**贪心格点合法化**收尾 |
| **区域盒不许重叠** | 否则 `separate()` 在边界上把器件推来推去 |
| **贪心要跑两遍** | 第一遍先落位的是拿「当时还没排好的邻居」判的 |
| **贴电源脚 vs 夹进区域的顺序** | **先贴脚，再夹区域**。反过来会把 SU 区的件全贴在区域边界上、正好堵住芯片那一圈 |
| **别沿固定射线堆去耦** | 多只电源脚的射线几乎平行，堆到第三颗就互相顶开。改成**在焊盘周围找最近合法空位 + 按轮次交错**（每轮给每只脚发一颗） |
| **候选位置先吸栅格再判间距** | 先判后吸的话，吸动的 ≤0.07mm 会把刚搜出的 0.30mm 余量吃掉 |
| **禁布通道用旋转多边形 + 逐段 buffer 并集，不能用凸包** | 扇形出线的中间那条缝会被凸包吃掉。用 `unary_union([LineString(seg).buffer(clear) for seg in segs])` |
| **芯片自己的出线区要从禁布里抠掉** | 不抠的话整圈去耦被挤到几 mm 外，而「离电源脚越近越好」这条更强 |
| **判重叠必须用真实旋转多边形** | 45° 摆放的方片，外接矩形面积比本体大 **41%**。用 AABB 会误报一片 |
| **链式拓扑别手写坐标** | 给规则（抽头位置、方向、串联次序），坐标按实测封装尺寸现算 |
| **手册坐标按本体中心** | 不是器件原点。偏心封装按原点排必错 |

## ④ 人布线

布完之后 AI 可以做的收尾：

### 电源线加宽

布线时用的是默认线宽（`copperThickness1oz` 的 0.254mm），
**改线宽模板不会动已有的线**，只能逐段改 `lineWidth`。

判据是 **IR 压降**不是温升：1oz 铜方阻 0.5mΩ/□，0.254mm 宽每毫米 2.0mΩ。

- ⚠ **不能用「中心线到障碍的距离 − 半宽」估最大宽度** ——
  加宽后**矩形的端角**会比中心线端点更靠近侧后方的障碍。必须**对真实多边形二分搜索**
- ⚠ **要两套障碍索引**：「还能加多宽」按邻居的**目标宽**膨胀；「现在是否违规」按**当前真实宽度**
- ⚠ **只加宽，绝不收窄**。原有问题只报告，不擅自改用户布好的线
- ⚠ **改完要能复位**（`--reset` 回 0.254 基线），否则算错了退不回来
- ⚠ 批量写会炸 id（编辑器合并共线同宽段），逐条 try/catch + **重读几何再跑一轮**

### 铺铜

**没有「重新铺铜」接口**。器件挪完之后内电层的避让是旧的，
DRC 会报一堆 `Plane Zone to TH Pad` / `Hole to Plane Zone` —— **得在编辑器里手动重铺**。

---

## ⚠ DRC：别在布线前跑

`pcb_Drc.check()` 会把错误写进 GUI 的 DRC 面板，而**布线前 Connection Error 有几百条**
（每个未连接焊盘一条）—— 编辑器就在**每个焊盘上画一个叉**。
canmv_serdes 两块板都发生过，用户两次来问「这些叉是什么」。

要跑的话：

```
pcb_Drc.check(strict, ui, includeVerboseError)
⚠ includeVerboseError=false **恒返回空**，不管 strict 传什么 —— 它不是「只报真实违规」
  （曾据此反复汇报「真实 DRC 违规 0 条」，那个数毫无意义：
    同一时刻 verbose 模式下有 15 条真实的 SMD Pad to SMD Pad 冲突）
正确做法：永远 verbose=true，然后自己按子类分：
  Connection Error                      = 飞线未连（布线前正常）
  Clearance Error / SMD Pad to SMD Pad  = 真冲突，必须修
  Plane Zone to TH Pad / Hole to Plane  = 内电层避让过期，重新铺铜即消
```

跑完记得告诉用户去清结果集。

# ★ 自动布线这一轮的全部教训（daikin-rcu 2026-09-29）

## 结论先行

**布局成功、布线失败。** 我的布线器按**自己的判据**是「0 短路、1 条未连通」，
跑 EDA 自己的 DRC 却是 **2261 条间距违规 + 559 条未连接**。已全部撤销。

→ **这正是「不看自己的账」那条铁律在 PCB 侧的翻版。**
  原理图那边的硬判据是「导 EDA 的网表」，PCB 这边就是「跑 EDA 的 DRC」。
  我自建的几何检查全绿，不代表任何事。

## 环境事实

| | 实测（4.1.60） |
|---|---|
| `pcb_Document.autoRouting()` | **哑的**。Promise 既不 resolve 也不 reject，4 分钟零铜线，EDA 本身照常响应（不是弹窗挡住）。传不传 `RoutingNets` 都一样 |
| `pcb_Document.autoLayout()` | 存在，未验证 |
| `pcb_PrimitivePour.create()` | **所有参数组合都被拒**（点数组 / 扁平数组 / `["R",…]` / `[x,y,"L",…]` / `createPolygon()` 的对象 / 3~9 个参数全试过）。→ 覆铜只能在 GUI 里点 |
| `pcb_PrimitiveLine.create(net,layer,x0,y0,x1,y1,w,lock)` | 可用，单位 mil |
| `pcb_PrimitiveVia.create(net,x,y,hole,dia,…)` | 可用 |

⚠ **更正 canmv_serdes 的一条笔记**：那里写「PCB 坐标两边一致」，**是错的**。
实测板框记录是 `["R",0,0,1968.5,1968.5,…]`（y 向下为正），而 API 报
`hole1 = (157.5, −157.5)` —— **PCB 也是 `api_y = −file_y`**，和原理图一样。

## 布局：一条老课重犯

skill 里为原理图记过「**不许碰 ≠ 线能过**」。我在 PCB 上又犯了一次：
`CLEAR` 设 0.35 mm 只保证器件不叠，而一根 0.254 的线加两侧 0.2 间距要 **0.654 mm** 通道。
结果 54 条网布不通 29 条，很多**连焊盘都出不来**。板子密度才 31%，是被自己挤死的。

## ★★ 封装本体尺寸必须用**焊盘实测**验证，不能抄数据手册

ESP32-WROOM-32E 数据手册是 18.0 × 25.5。我据此写进 `BODY`，
而器件在板上 `rot = −90`，代码里 w/h 一互换就变成 25.5 × 18 —— **整个转置了**。

后果：顶层禁区画错方向，**模组自己的 35 个焊盘落在禁区内部被封死**，
13 条网永远布不通。改正后**一次就降到 1 条**。

→ 判据：拿焊盘坐标反推。U3 的焊盘在 x=16/34（相距 18）、y 跨 11.5
  ⇒ 世界坐标下是 18 宽 × 25.5 高 ⇒ 本地必须写 (25.5, 18.0)。

## 布线算法：协商式拥塞是对的，贪心不是

单趟贪心布不通 25~29 条，而**每条单独跑都能通** —— 瓶颈是拥塞不是几何。
无效的尝试（别再试）：

| 尝试 | 结果 |
|---|---|
| 加大器件间距 0.35 → 0.9 | 29 → 27 |
| 多趟重排（失败的下轮先布） | **更差** 27 → 39/41/48 |
| 过孔代价 28 → 14 → 4 | 29 → 25 |
| 焊盘间距环「争议格判死」 | **更差** 29 → 37（把焊盘封住了） |

有效的是 **PathFinder 协商式拥塞**（Ebeling 1995）：允许暂时重叠，
每轮给被争用的格子累加历史代价，`present_factor` 递增，迭代到无争用。
实测**铜压铜 293 → 0**（21 轮），未连通 1 条。

配套的三条实现要点：

1. **占用要记「是谁占的」**，不能只记 0/1。否则一条网布完第一段后，
   **自己的铜和间距带把自己封死**，多脚网必然剩下连不上。
2. **分清「铜压铜」和「间距紧」。** 前者是短路必须清零，后者只是 DRC 警告。
   只看后者的话数字在 5000~7000 震荡，**看不出其实已经收敛**。
3. **拉直必须是收敛之后的后处理。** 放在协商循环里，实际铜和 A* 依据的
   代价场不一致，协商自己跟自己打架（短路卡在 400~500 不降）。
   放在收敛后并只接受「不进入别网已占格」的拉直：**2574 段 → 696 段**。
   ⚠ 拉直后要**重新加密**再去标占用，否则中间那段铜没被记进去。

## ★ 为什么最终还是失败：占用模型少了两件东西

DRC 打脸的两条，都是我的模型里**根本没有**的概念：

1. **过孔没有占位。** `Track to Via 738`、`Hole to Track 484`、`SMD Pad to Via 196` ——
   我只按**线宽**留间距，而过孔 Ø0.6 比 0.2 的线宽得多。
2. **铜线端点没有真正落到焊盘上。** `Connection Error 559` ——
   端点落在布线栅格上，离焊盘中心可能差半格，EDA 判未连接。
   → 每条线的**首尾必须强制吸附到焊盘中心**，不能停在栅格点。

→ 下次从这两条开始，而不是从头再写一个布线器。
