# 验收判据

每个阶段都要有**硬判据**。「看起来对」不是判据。

---

## 原理图

| # | 判据 | 工具 | 不过怎么办 |
|---|---|---|---|
| 1 | 所有引脚**落 10 栅格**（x 和 y 都要查） | `gridcheck.off_grid()` | `nudge_to_grid()` 自动挪半格 |
| 2 | 位号集合与计划**完全一致** | 读回 `getAll()` 比对 | 补建 / 删多余 |
| 3 | 每个显示值 ↔ **一个料号**（一一对应） | 脚本内校验 | 逐个阻值查真料号 |
| 4 | **不许有单节点的命名网络** | `netcheck.report()` | 找漏接的脚 |
| 5 | 未接引脚**只有 NC 和明确不用的脚** | `netcheck.report(expect_nc=…)` | 补连 |
| 6 | 改动前后**网络节点数没有意外变多** | `netcheck.diff()` | 查是否误并网（L 形路径压到别人） |
| 7 | 标记朝向**不压在支线上** | `gridcheck.check_label_orientation()` | 镜像 |
| 8 | **人打开看过** | 眼睛 | —— |

⚠ **导线条数不是判据**：编辑器会合并共线同宽段。
daikin-rcu 建 84 段读回 81 段，正常。

⚠ 判据 6 是最容易被忽略、后果最隐蔽的一条。
典型事故：把 2 节点网改成直连线，L 形路径压到第三个引脚 → 被判成 T 形连接 →
整条网络被静默并进 GND。**图上看不出来，节点数对比才看得出来。**

⚠ 判据 8 不能省：符号本体和位号/数值文字的**包围盒 API 读不到**，
器件叠没叠只有人眼能判。

## PCB

| # | 判据 | 说明 |
|---|---|---|
| 1 | 器件**不重叠** | ⚠ 必须用**真实旋转多边形**求交，不能用 AABB（45° 方片的外接矩形大 41%） |
| 2 | 全部在**板框内** | 重力模型结构上不认识板框，必须另外夹 |
| 3 | 关键器件的**锁定位置没被动过** | 人定的就是人定的 |
| 4 | 天线**净空区**无铜、无走线（所有层） | 按模组手册 |
| 5 | DRC | ⚠ 必须 `verbose=true`，然后**自己按子类分**（见 `pcb-workflow.md`） |
| 6 | 电源网 **IR 压降**在预算内 | 1oz 铜 0.254mm 宽 ≈ 2.0 mΩ/mm |

⚠ **布线前别跑 DRC** —— 会在 GUI 每个未连接焊盘上画叉，用户会来问「这些叉是什么」。

# ★ 第三个验收维度：**料对不对**

## 为什么要单列出来

daikin-rcu 2026-09-29：四页原理图网表全绿、几何检查也过，**所有电容电感却不显示值**。
用户一眼看出来，而我所有的自动检查**一条都没报**。

根因不是写错了代码，是**验收判据有盲区**：

| 维度 | 我有的检查 | 覆盖了吗 |
|---|---|---|
| 连得对不对 | 导网表逐条核对 | ✓ |
| 画得好不好看 | 几何审查、交叉计数 | ✓ |
| **料对不对** | **无** | ✗ |

→ 网表里只有 `Designator` / `Device` / `Footprint`，**不带值**。
  几何检查更不带。所以「值是空的」这件事**在我的体系里根本不可见**。

**教训：判据覆盖不到的维度，等于没做。** 加检查之前先问「我的判据覆盖了哪几个维度」。

## 具体的坑

### 1. `create()` 放下来的器件，参数属性是空的

`lib_Device.getByLcscIds()` + `sch_PrimitiveComponent.create()` 放下来的器件：

```
supplierId      = "C15850"              ✓ 是正经商城料
manufacturerId  = "CL21A106KAYNNNE"     ✓
name            = "={Value}"            ← 显示名是**公式**
otherProperty.Value = ""                ← 公式引用的属性是**空的**
otherProperty.{Tolerance, Voltage Rating, Description} = ""   全空
```

**库里器件的参数不会跟着实例过来。** 于是图上什么都不显示 ——
器件是对的，只是"看不见值"。

→ 放完器件要**补 `otherProperty.Value`**（带耐压的拆成 `Value` + `Voltage Rating`）。
  ⚠ `otherProperty` 必须**整份读出来合并再写回**，只塞新键会抹掉别的键。

### 2. 值和料号是两列独立数据，没有任何东西保证它们一致

规格表里「值」和「LCSC 料号」是两列，改一列不改另一列没人拦得住。
daikin-rcu 出过两次：

- 早期：**所有电阻共用一个料号** C4216(33k)，图上值各不相同、BOM 全是 33k
- 本次：R44 规格写 `C21189/0R`，实际放的是 `C2907002/FRC0603F1001TS`(1kΩ)

→ **值必须能从厂商料号解码出来再对一遍**，不能靠人维护两列的一致性。
  0603 常见编码：`FRC0603F1001TS` / `0603WAF4701T5E` / `RC0603FR-0710KL`
  → 取那段数字，`ABCD` = `ABC × 10^D`；带 `R` 的是小数点（`4R70` = 4.7Ω）。

⚠ 比较时要认**中缀写法**：`4k7` == `4.7kΩ`、`1M1` == `1.1MΩ`。
  第一版没认，8 个里 7 个是误报，差点去"修"本来就对的。

### 3. ⚠⚠ 对账时**不要用一方去覆盖另一方**

我发现 R44 不一致后，顺手把**规格里的 0R 写到了器件上** ——
于是图上显示 `0R`、BOM 里发的是 1kΩ。
**这比没有值更危险**：原来是"看不见"，改完变成"看见的是错的"。

→ 对账的产出是**报告**，不是修复。哪一侧错了只有人知道
（是选型时改了料号忘了改注释，还是注释是对的而料号选错了）。
  非要写的话，**以实物（料号）为准**，因为 BOM 按料号发货。
