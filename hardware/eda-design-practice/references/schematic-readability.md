# 原理图可审性规则

网表对 ≠ 图能看。这些规则全部是为了**让人能审图**，不影响电气正确性。
但它们不是「美观问题」—— 一张人审不了的图，等于没有人在审。

---

## R1. 不要整张图都靠网络名连接

**场景**：给一页上的器件建立连接关系时
**机理**：只给导线命名、不画实际连线，网表完全正确，但人看到的是一堆**孤立的短线头**，
无法用眼睛追踪信号走向，也就无法审出接错的地方。
**代价**：canmv_serdes 早期版本整图靠网络名，用户要求返工重画。
daikin-rcu 的 P1 初版同样问题（局部网络全是无标记的隐形短支线）。
**出处**：canmv_serdes（首次，用户纠正）；daikin-rcu P1（二次）
**失效条件**：真正跨页的信号只能靠端口符号，这是标准做法，不在此列。

### 正确做法：三分法

| 画法 | 用在哪 | 是否加网络名 |
|---|---|---|
| **直接画线** | 本页、2 节点、路径干净 | **不加名，也不加符号** |
| **地/电源符号** | GND 和各电源轨 | 符号自带名，导线不再命名 |
| **跨页端口** | **只给真正出现在 ≥2 页的网络** | 符号自带名，导线不再命名 |

判断「真跨页」要**从全部页的网表算出来**，不能凭印象往 PORT 集合里塞。
daikin-rcu 初版把 27 条网络都当跨页处理，实际只有 11 条是。

## R2. 同一网络里**彼此靠近**的引脚要用导线串起来共用一个符号

**场景**：一页上同一个网络有多个引脚 —— 尤其是芯片/连接器周围那一圈
（多个地脚、一排去耦电容、分压电阻串、电容组）。

**机理**：每个脚各挂一个符号，有三重坏处：符号互相叠、把图面塞满；
**掩盖了「它们本来就该连在一起」这个信息**；而且人审图时无法用眼睛追踪，
只能逐个读文字去脑内配对 —— 等于没在审图。
就近用实线连成一个点、只引一个符号，图面干净、意图明确，**这才像人画的**。

**代价**：daikin-rcu 初版 P1 页 30 个器件挂了 72 个标记、P3 是 16 个器件对 43 个标记
—— 标记比器件还多。用户的原话：「好多规则可以泛化…如果能做到这样就像人类了」。

**出处**：canmv_serdes（首次，用户纠正，当时只说了 GND）；
daikin-rcu 2026-09-28（用户**手工改了半页 P2 做示范**，并要求泛化到所有网络）。

**失效条件**：见下面的修订 —— **分界不是距离，是网络的种类**。

### ★ 修订（2026-09-28 当天）：信号网全连，只有电源地才看距离

第一版对所有网络一律用距离阈值 110。用户看完 P1 当场指出问题：
`TVL_N` / `TVT_N` / `AIO_BUS` 明明该连到主芯片 U1 上，却因为 210~270 的距离
被判成两簇、各挂一个符号。他的原话：

> **「你不应该避免跨线交叉，在人类原理图中，它是不可避免的」**

**人画图的真正分界是「信号走实线、电源地走符号」，不是距离。**

| 网络种类 | 怎么连 | 为什么 |
|---|---|---|
| **信号网** | **全连**，不看距离，该交叉就交叉 | 信号的走向就是要让人眼睛能追 |
| **电源 / 地** | 按距离就近分簇，每簇一个符号 | GND 在 P1 上 14 个脚横跨 1140，硬连成一棵树才是灾难 —— **那正是地符号存在的理由** |

改完的实测：P1 的标记 72 → **19**、P2 34 → **18**、P3 43 → **25**，网表不变。
（只改距离阈值时是 52 / 27 / 38，差距全在信号网上。）

### ★ 配套：引脚有朝向，导线不许从引脚背面离开

用户同时指出的第二条：

> 「R13 右边端子…你可以向上、向右、向下，**但你不能向左**」

向左就是从元件本体上压回去，人不会这么画。

**引脚朝向能直接读到，不用猜几何**：`getAllPinsByPrimitiveId` 回的引脚对象带
`rotation`，映射（原理图 API 坐标，y 向上，逆时针）：

| pin rotation | 0 | 90 | 180 | 270 |
|---|---|---|---|---|
| 向外方向 | 右 (1,0) | 上 (0,1) | 左 (−1,0) | 下 (0,−1) |

实测标定：R13 原点 x=1000，脚 2 在 x=1020 且 rot=0、脚 1 在 x=980 且 rot=180；
Q1 的 S 在下方 rot=270、D 在上方 rot=90。

约束（★ 两端的判法是**反的**，很容易写错）：

```
起点 a：第一段方向 f，禁止 f == −da
终点 b：最后一段是**射入** b 的，方向 l；从 b 往外看是 −l
        禁止 −l == −db，即**禁止 l == db**
```

⚠ **只过滤不生成，会一条候选都剩不下。** 目标在引脚背面时，直连和普通 L 形的
第一段全是反向的。必须**主动生成「先沿引脚朝向走出去 e，再拐」这一族候选**
（e 取 0/20/40/…/240，两端各取一次），再按总长排序。

⚠ 排序**不能只按长度**：最短的往往是「贴着引脚 10 个单位就拐」，那条线会从
元件本体上擦过去。符号本体的包围盒 API 读不到（见 R6），只能用
「**首尾段至少 20 再拐**」这个偏好去近似「别压着元件走」。

→ 顺带把符号支线也改成沿引脚朝向外伸。旧版按「引脚在包围盒哪一侧」猜方向，
  对旋转过的器件和多排引脚的芯片会猜错。

### ★ 再一条：导线不许从**元件本体**或**网络符号**身上穿过去

用户 2026-09-28 第三次指出：P1 上 `U1.2→R6` 那根线正好压在 `MS_DIN` 符号上、
P2 上 `R22→R23` 压在一个端口符号上。

**元件本体的矩形能算出来**，不用猜，也不受「包围盒 API 读不到」的限制：

> 引脚的 `x,y` 是**接线点（外端）**，沿引脚朝向**回缩 `pinLength`** 就是本体边缘；
> 对所有内端点取包围盒即本体。只有一排引脚时某方向退化成 0，补一个最小厚度。

实测：R13 两脚在 x=980/1020、`pinLength`=10 → 本体 `x[990,1010]`，
y 退化补成 `[520,540]` —— 和实际电阻符号吻合。

判穿越要判**矩形内部**、不判边界：导线本来就从引脚出发，而引脚正好在本体边缘上，
按闭区间判会把所有正常连线都否掉。

#### ⚠⚠ 顺序陷阱：符号是后放的，画线时它还不存在

符号在第二遍才放，第一遍画线时并不知道它会落在哪 —— 这正是用户看到的那两处重叠。
必须加**第零遍：先按「假设所有连线都成功」把符号位置算出来占住**，第一遍再去躲。

⚠ **预留要从「引脚」起算，不能只圈符号本体。**
只圈本体的话，引脚到符号之间那段**支线**是敞开的，长导线照样从那儿穿过去，
第二遍就「找不到能放符号的支线位」—— **符号放不下，网络当场悬空**。
2026-09-28 实测栽在这上面的：P1 的 `VRAW` / `VCC5`、P3 的 `+3V3` / `ESP_TXD`。
→ 预留长度 = `STUB + 符号长度`，起点是引脚。
→ 第二遍放符号时，标准支线长被占了要**伸长再试**（30/50/70/20/90）：
  线难看只是观感，**符号放不下是电气错误**。

#### 这条必须是**软约束**

「不穿越」是观感，「连不上」是电气。一条候选都不剩时，**宁可穿过去也要把线连上**，
然后**如实报告有几根是让步的**（本轮 P1 4 根、P2 4 根、P3 7 根）。
退回加符号会让图更难看，还把刚减下去的符号数加回来。

#### ⚠ 只躲「元件本体」不够 —— 用户指的往往是**网络符号**

2026-09-28 第一版只做了元件本体，用户复查后说两处**一点没变**：
一量才知道 **本体穿越 0 处、符号占位穿越 4 处**。三个独立的漏洞：

1. **放符号时从没检查过「符号本体会不会压在导线上」**，只检查了支线的电气冲突。
2. **检查要对所有导线做，包括本网自己的。** 用户指的 `MS_DIN`、`R22/R23` 两处，
   压上去的正是**同一个网**的导线 —— 按「别的网」过滤一个都查不出来。
3. **第零遍预留的位置和第二遍实放的位置要是同一个点。** 不一致的话，
   第一遍辛辛苦苦躲开的是个没人用的坑。
   → 第二遍的候选表里，把预留位置**排在最前**。

还有一条顺序坑：**符号是一个一个放的，后建的支线会压到先放好的符号**
（P2 的 `VSTORE`）。→ 维护一个 `placed` 列表，新支线也要躲它。

#### 给符号加 **L 形支线**，候选数量才够用

只允许「沿引脚朝向直出」时，候选数 = 引脚数 × 长度数，芯片边上常常一个合法位都没有。
加上「出来一小段再拐个弯」（4 个拐向 × 3 个拐距），候选多一个数量级 ——
P1 直出时 `MS_DIN` / `HBS_B` 无解，加 L 形后 P2 / P3 直接降到 **0 处重叠**。
人画图本来也是这么放标签的。

#### 写成脚本，别靠眼睛

这类问题**网表查不出来**（电气上没错），而「人眼看一遍」在多页工程上不可重复。
→ `lib/overlapcheck.py`：算出每个器件的本体盒和每个符号的占位盒，
  找出穿过它们的导线段，逐条打印。**改完必跑。**

#### 什么时候它是布局问题，不是连线问题

P1 最后剩 2 个符号无解。量一下就明白：U1 左侧 **12 个引脚全部朝左**、
y 从 490 到 630、间距只有 10~20，而一个符号占位半高 15 —— **一个符号要吃掉 3 条脚道**。
这不是路由能解决的，是**器件摆放**（人的领域）决定的。
→ 报告清楚「剩几处、为什么」，把决定权交回去，不要硬凑。

### 实现（★ 安全性是这条规则的全部难点）

```
① 按曼哈顿距离对同网引脚做**单链聚类**
② 簇内求 MST（不是按坐标排成一串 —— 那会产生横跨整簇的长边）
③ 逐条画串联线，**路径要躲开不属于本网的引脚**（见 R5）
④ ★★ 只有 create **真的成功**了才并进连通分量
⑤ 按**实际连通分量**发符号 —— 不是按「打算合并的簇」发
```

⚠ **④⑤ 是这条规则唯一会要命的地方。**
2026-09-28 第一版的写法是「先把簇成员从待办里划掉、只留一个符号」，
而串联线创建失败的异常被吞了 —— 那些脚**既没串联线也没支线**，
**静默悬空**：网表从 55 条掉到 50 条，十几个脚飘了（含 `U1.25(EP)`、`U1.8(HN)`、
整条 `MS_DIN`）。**图上完全看不出来。**

按 ④⑤ 写就在结构上不可能悬空：最坏情况（所有串联线都失败）退化成
「每脚一个符号」，也就是改进前的行为。**让失败路径退化到旧行为，而不是退化到悬空。**

### 顺带的推论：整条网连成一坨就别放符号了

如果一条网络的**全部**引脚都进了同一个连通分量，而且它不跨页、也不是电源/地，
那它**一个符号都不需要** —— 连接关系已经画出来了，再挂名字是重复（见 R3）。
电源和地例外：即使连成一坨也要引**一个**符号，那是行业惯例。

### 实测（daikin-rcu，2026-09-28）

| 页 | 器件 | 标记（改前） | 标记（规则后） |
|---|---|---|---|
| P1 | 30 | 72 | **52** |
| P2 | 21 | 34 | **27** |
| P3 | 16 | 43 | **38** |

且网表不变：80 器件 / 55 网络 / 单节点 0 / 规格逐条对上。

**和人手工改的结果对照**（P2，用户改了一半）：11 条网络里 **7 条符号数完全一致**，
另外 4 条规则合并得更多 —— 而那 4 条恰好是用户还没轮到的。
→ **规则复现了人的判断，并把它做完了。** 这是「规则泛化成功」的判据，
比「我觉得好看」硬得多。

## R2b. 交叉数是**代价函数**，不是对错判据 —— 但一定要拿它排序

**场景**：同一条连线/同一个符号有多个合法落位时。

**机理**：X 形穿越**不连接**，所以交叉不是错（人画图也躲不开，用户原话）。
但**交叉多 = 图难读**。而生成器天然会「找到第一条合法的就用」——
合法候选常常有十几个，白白挑了最差的那个。

**代价**：daikin-rcu 2026-09-28，四页攒了 **78 处**交叉，纯粹因为选路和符号落位
从没看过这个指标。

**出处**：daikin-rcu（用户提出「布线完成后应该有微调阶段，尽量把线拉顺」）。

**失效条件**：不能当硬约束。为了少一个交叉而连不上线、或退回加符号，是赔本的。

→ 做法：候选先过**硬约束**（电气：不压引脚、不共线重叠、方向合规），
  再过**软约束**（不穿元件/符号），最后在剩下的里**按交叉数取最小**（同分取较短）。
  实测四页 **78 → 49 处，网表一字未变**（P3 从 20 降到 **0**）。

### 计数口径

真正穿越 = 一横一竖、交点落在**两条线段的内部**。端点相接不算 —— 那是连接。
同一网络之间不算。

## R2c. ⚠ 一个失败的尝试：按「交叉数」去建议旋转/镜像

用户提议：「减少交叉除了移动位置，试不同的 rotation / x-mirror / y-mirror
收效可能更大」—— 想法是对的（两脚件翻个面就换了引脚顺序，还不用挪位置）。

**几何标定**（实测，别猜）：

```
器件 offset = mirrorX( CCW旋转(local, r) )       mirrorX: (x,y) → (−x,y)
引脚 rotation = (local引脚rot + r) % 360，镜像时方向再翻 x
⚠ 器件的 rotation **存储值 = 传入值**（网络符号那套是「存储 = 360 − 传入」，别混）
⚠ API 只有一个 `mirror`（x 镜像）；**y 镜像 = rot180 + x 镜像**，
   所以遍历 4 个 rotation × 2 个 mirror 就已经覆盖全部 8 种摆法
```

**但我实现的建议器给出了错的建议。** 它逐个器件试摆法、只重算该器件的连线、
数交叉 —— 头 4 条建议里：

| 建议 | 结果 |
|---|---|
| R1 镜像（估 −2） | `HP_N` **断了** |
| R2 转 90°（估 −1） | 引脚落进死角，出不来线也放不下符号，`AIO_BUS` 断了 |
| C1 / R9 镜像（估 −2） | 落地后交叉**一个没少** |

净效果：交叉 21 → 16，**但坏了 2 条网络**；把断线的两个退回后，交叉又回到 21。

**教训**：**优化一个代理指标时，必须把可行性约束一起带进去。**
我的建议器只数交叉，没检查「这个摆法下还连不连得出去、符号还放不放得下」——
于是它推荐的正是那些把引脚转进死角的摆法。

→ 要做对，建议器必须**按完整流水线去评估每个候选**（重路由 + 重放符号 + 网表），
  而不是用一个便宜的代理。代价高得多，但这是唯一可信的做法。
→ **这次是网表把它抓住的**，再次说明验收判据不能省。

## R2d. 串联之前先问：这条线会横穿几条异网出线？

**场景**：R2 的「同网邻近引脚串起来共用一个符号」，遇到**连接器的一列引脚**。

**机理**：连接器的电源脚和数据脚常常**交错排列**（Type-C 尤其典型）。
把同网的脚竖向串起来，那条竖线**必然横穿中间所有数据脚的出线**。

**代价**：daikin-rcu P4 的 **17 处交叉全部来自这一条**
（`VBUS`/`GND` × `CC1_N`/`CC2_N`/`USB_D±`，全挤在 x=450/460 两列上）。

→ **这不是布局能解决的，是「串联」这个决定本身错了。** 这几个脚该各挂一个符号。

**出处**：daikin-rcu 2026-09-29（用户指出 P4 的交叉，顺着查到根因）。

**失效条件**：**只对电源地这么判**。信号网不串就得挂端口，那更难看。

→ 实现：串联前用异网引脚的**出线支线**做碰撞计数，`≥2` 条就不串。
  实测 P4 交叉 **17 → 7**，四页合计 46 → 32。

## R2e. 地符号本体朝下、电源符号本体朝上

**场景**：放 netflag。

**机理**：行业画法 —— **地的接线端朝上、本体朝下**，**电源的接线端朝下、本体朝上**。
人扫一眼就知道哪是地、哪是电源，不用读文字。

**出处**：daikin-rcu 2026-09-29（用户提出：「这种画法更适合人类审阅」）。

**失效条件**：引脚朝向决定了支线方向，直出的支线给不出竖向符号时，
要靠 L 形支线（出来一小段再拐），而 L 形更长、更容易被占位检查否掉。

⚠ **排序要把惯例放在交叉前面**：交叉是网表拓扑的原生属性、消不掉；
  朝向惯例是**给人审图用的**，能做到就该做到。

⚠ 实测只做到 **65%**。瓶颈不在排序（换过顺序只涨了 3 个百分点），
  而在**合惯例的候选被占位检查提前否掉了**。要再提高得给 L 形支线留更多空间。

## R2f. 从「人手工改过的一页」反推规则 —— daikin-rcu P2 2026-09-29

用户手工重排了一页已生成的图「让它更符合人类 review」。逐项 diff 之后，
**他的版本在我能量的每一个指标上都更好**：

| | 生成的 | 人改的 |
|---|---|---|
| 交叉 | 4 | **2** |
| 导线穿元件本体 | 1 | **0** |
| 导线压符号 | 5 | **1** |
| 电源地符号朝向合惯例 | 65% | **100%** |
| 共行/共列对齐的器件 | 5x + 6y | **10x + 12y** |
| 用 270° 的器件 | 4 | **0** |

★ **可审性和几何质量不是此消彼长，是一致的。** 别把「好看」当成要拿正确性去换的东西。

### (1) 电源地符号的**朝向和位置**是硬约束，不是 tiebreaker

- 朝向：地的本体朝下（接线端朝上）、电源的本体朝上（接线端朝下）
- 位置：于是地符号必然落在它所接引脚的**下方**、电源符号落在**上方**（人做到 17/18）

我只做到 65%，原因是我把它排在「少交叉」**后面**当次要键。
人做到 100% 说明**它总是可达的** —— 人是通过调整走线和器件去迁就这条，而不是反过来。

→ **朝向当硬约束，让走线去适应**：L 形支线、换一个接入脚、必要时挪器件。

### (2) 对称两脚件只用 0° 和 90°，不用 270°

人把 4 个 270° 全消掉，90° 从 7 个涨到 15 个。

机理：电阻、无极性电容**引脚顺序没有意义**，270° 相对 90° 只是把两脚对调 ——
换不来任何东西，却让位号和数值倒着读。

→ 姿态枚举里对**对称两脚件**直接排除 180/270。有极性的（二极管、LED、极性电容）不在此列。

### (3) 同类器件**对齐成行或列**

电容组 C11/C10/C13/C14 全落在 y=680；分压 R22/R23 同在 x=1050。
对齐数翻倍（5x+6y → 10x+12y）。

机理：**对齐是「这几个是一伙」的视觉信号**。等值同类器件散着摆，读起来是噪声。

→ 可做成后优化：小幅移动把器件吸到共享的行/列上（不破坏约束就接受）。

### (4) 功能块**整体搬迁**，块内按电气次序排

ADC 分压 R22/R23/C16 从最左（x 310~400）**整体**搬到最右（x 1015~1050），排成一列，
且**电源在上、地在下**（R22 y=725 → R23 y=650 → GND 符号 y=600）。

我的地形布局把它们判成「孤岛」后**一字排开在角落**，没把它们当成一个块。

→ 孤岛/功能块要**作为整体**停泊，块内保持自己的拓扑次序，不要按索引摊平。

### ⚠ 一个反直觉的观察：人摆的器件有 8/21 不落 10 栅格

（引脚落在 745、1015 这类坐标上。）网表照样全绿 —— 因为**人把导线也画到了那些坐标上**。
再次印证 R7 的修订：**真正决定通断的是「导线端点和引脚坐标重合」，不是栅格本身**。
→ 不要为了对齐栅格去动人摆好的器件。

### 实现（R2f 的 1、2 两条已进生成器，2026-09-29）

**朝向惯例做成分层过滤，不是排序键：**

```
电气(硬) → 朝向惯例(硬) → 不压线(软) → 交叉 → 长度
```

⚠ 我第一版把「符号不压线」和惯例并列当硬约束，惯例只到 68%。
**压线只是观感、可以让步；惯例是给人读图的语义，不该为它让路。** 换成分层后 89~93%。

**姿态限制要连初值一起归一：**

⚠ 只限制「候选集合」是不够的 —— 器件**本来就在 270°** 又没有更优候选时，
它会原地不动（实测 P3 的 R31 一直停在 270）。
→ 读进来就把对称两脚件的 180→0、270→90 归一。改完四页 **270° 全清零**。

**放不下符号时的最后手段：并入同网。**

⚠ 收紧约束之后必然有放不下的（P1 的 C7 地脚），直接放弃 = **悬空**。
→ 最后手段是**用导线连到同网已放好符号的那一簇** —— 多一根线，远好过断一个脚。

### 效果（四页）

| | P1 | P2（人手工） | P3 | P4 |
|---|---|---|---|---|
| 朝向合惯例 | 89% | 100% | 89% | 93% |
| 对称件用 180/270 | **0** | 1 | **0** | **0** |
| 对齐 | 25/30 | 22/21 | 6/16 | 8/17 |

⚠ **代价要讲清楚**：把惯例提到「不压线」前面之后，**符号压线从 4 处涨到 35 处**。
这是我们明确选择的次序（语义优先于观感），但它是个真实的退步，
下一步该去收的是**给符号留位**，不是把次序换回去。

→ 检查工具：`lib/stylecheck.py`（朝向 / 旋转 / 对齐三项，网表和几何都查不出来）。

## R3. 已经有连接符号了，就不要再给导线加网络名

**场景**：在支线末端放了地符号 / 电源符号 / 跨页端口
**机理**：符号本身会显示网络名。如果导线也设了 `net` 属性，**同一个名字在图上出现两次**，
密集区域文字糊成一片。
**代价**：daikin-rcu 四页共 78 个器件却有 194 个标记，用户反馈「验证看」。
**出处**：daikin-rcu（用户提出）
**失效条件**：没有符号的导线（比如局部多节点网络）必须靠 `net` 属性命名，否则连不上。

→ 实现上：**有符号时 `sch_PrimitiveWire.create(path)` 不传 net 参数**，
让符号定义网络。已验证网表不受影响。

## R4. 连接符号不要压在它所连接的网络上

**场景**：放地符号 / 电源符号 / 跨页端口
**机理**：符号有方向。若本体朝向与支线方向相同，符号就压在导线上。
**代价**：daikin-rcu 四页共 109 个符号压线。
**出处**：daikin-rcu（用户提出）
**失效条件**：无。

### ★ 朝向约定（2026-09-28 用户目视逐个确认，不要凭推测改）

两个**独立**的事实，缺一不可：

**① 每种符号的约定不同，不能共用一张表。**
「传入的 rotation → 本体伸出方向」（API 坐标 y 向上；引脚在符号原点）：

| 传入 rot | Ground | Power | netport BI/OUT | netport IN |
|---|---|---|---|---|
| 0 | 下 (0,−1) | 上 (0,1) | 右 (1,0) | 左 (−1,0) |
| 90 | 左 (−1,0) | 右 (1,0) | 下 (0,−1) | 上 (0,1) |
| 180 | 上 (0,1) | 下 (0,−1) | 左 (−1,0) | 右 (1,0) |
| 270 | 右 (1,0) | 左 (−1,0) | 上 (0,1) | 下 (0,−1) |

**② 存储值 = (360 − 传入值) % 360**（五种符号一致）。
所以**生成时查 `PASS_TO_BODY`，回读检查时查 `STORED_TO_BODY`**，两者不能混。

⚠ **朝向只能在创建时定**：`sch_PrimitiveComponent.modify` 只认
`componentType === "part"`，对 netflag/netport 报「仅当器件类型为元件时允许使用该函数进行修改」。
要改只能**删了重建**。

### ⚠ 这条规则的教训比规则本身值钱

第一版我只测了 GND 就把结论推广到所有符号，而且**检查器和修复器共用同一张凭感觉写的表**
—— 自己验自己，「修好了」只是自洽，实际四个方向全错、越修越糟（51 → 92 → 109）。

**符号本体的包围盒 API 读不到，这个约定在 API 侧无法自证，只能靠人眼测一次。**
测完写进 `lib/gridcheck.py` 的 `PASS_TO_BODY`，以后所有项目直接查表。

→ 对应 `GOVERNANCE.md`：**没有独立验证的约定不能当规则用。**

## R5. 直连线必须做路径碰撞检查

**场景**：把 2 节点网络从「标记」改成「直接画线」
**机理**：EasyEDA 里**端点落在另一条线上 = T 形连接**（连通），**X 形穿越 = 不连接**。
L 形路径很容易从第三个引脚上压过去，于是被判成 T 形连接。
**代价**：daikin-rcu / 2026-09-28：`IO12_N`、`LED_A`、`LED_N` 三条网络被**静默并进 GND**，
GND 从 43 个节点涨到 48。**图上完全看不出来，只有导网表才暴露。**
**出处**：daikin-rcu P3（首次，但机理确定且代价严重 → 直接晋升）
**失效条件**：改用网络标签而不画实线时不适用。

→ 画直连线前，检查两条候选 L 形路径是否压到**不属于本网络**的引脚；
都不行就退回用标记。见 `lib/gridcheck.py` 的 `seg_hits()`。

### ★ 修订（2026-09-28）：只躲引脚不够，**共线重叠**同样是短路

开始画长导线之后（见 R2 修订：信号网全连），P1 的网表从 55 掉到 52：

```
SRA_N  → 并进 MS_DOUT      (U1.23/R12.2 和 U1.1/R5.1 短了)
TERM_N → 并进 BIO_BUS      (R13 的两个脚被短接)
```

**两处都没有压到任何引脚。** 是两条**不同网络**的导线**共线重叠** ——
编辑器会把共线段合并。狗腿路由按栅格扫中间列，两条端点相近的网
**极易选中同一列**，所以这个检查不能省。

会被判成「连上」的三种情形（**X 形穿越不在其列 —— 那是安全的、也是必然的**）：

| | 情形 | 后果 |
|---|---|---|
| ① | 和别的网的线**共线**且有交集（哪怕只重合一个点） | 被合并 |
| ② | 我的**拐点或端点**落在别的网的线上 | T 形连接 |
| ③ | 别的网的线的**端点**落在我的线上 | T 形连接 |

★ **「交叉」和「重叠/搭点」在图上长得差不多，电气上一个没事一个是短路，
   而且只有网表能发现。** 这是允许交叉之后必须补上的那一课。

→ 实现见 daikin-rcu 的 `build_page.py:wire_conflict()`。
  同时要注意：放符号的支线**也要过这个检查**，而且连线要**分两遍走** ——
  先把全网导线画完，第二遍再放符号，这样支线末端才有完整的障碍物可躲。

## R6. 器件间距按实测符号尺寸留，API 读不到本体包围盒

**场景**：批量放置器件
**机理**：`getAllPinsByPrimitiveId` 只给**引脚**坐标，**符号本体和位号/数值文字的包围盒读不到**。
所以「器件叠没叠」在 API 侧根本查不出来。
**代价**：daikin-rcu 首次按 20~30 的间距放，R5/R6/R12/R15 和 R9/R10 全叠在一起，用户在编辑器里看出来的。
**出处**：daikin-rcu（首次，但机理确定 → 晋升）
**失效条件**：无。

实测符号尺寸（EasyEDA Pro，0.01 inch 单位）：

```
竖放 R/C    引脚 y = 原点 ±20 → 跨度 40 → **中心距至少 60，建议 80**
横放 R      引脚 x = 原点 ±20
横放 C      引脚 x = 原点 ±15（1206 等大封装）
SOT-23      x 原点−20~原点，y 原点 ±20
SOP-4 桥堆  x 原点 ±25，y 原点 ±5
2P 端子     x 原点 ±5，y 原点 −20
```

→ **放完必须请人打开看一眼。** 这是铁律「在 EDA 里打开看过才算完成」的直接后果。

## R7. 坐标系与栅格

**场景**：任何写坐标的操作
**机理**：原理图 API 的 **y 向上为正**，文件格式里 **y 向下为正**（`api_y = -file_y`）。
单位 0.01 inch，栅格 10。**不落栅格网表里就是断的。**
**代价**：daikin-rcu 多次撞到（MB10S / J1 / C1 / C2 / C3 / C21 / J3 / C13 / C14）。
**出处**：canmv_serdes（首次记录）；daikin-rcu（二次，且发现只查 y 不够）
**失效条件**：PCB 侧两个坐标系一致，本条只适用于原理图。

⚠ **器件引脚偏移常见 ±5/±15/±25，这时原点要落在半格上**引脚才落 10 栅格。
放完要**全量检查 x 和 y 两个方向**（daikin-rcu 曾只查 y，漏掉 MB10S 的 x=965）。
见 `lib/gridcheck.py` 的 `check_grid()`，它会自动微调。

### ⚠ 精确一点：真正决定通断的是「导线端点和引脚坐标重合」，不是栅格本身

daikin-rcu P4 实测：用户把 R41 放在 x=**175**（引脚不落 10 栅格），
但他自己把导线也画到了 x=175 —— **网表里 CC2_N 照样是 2 个节点，通的**。

栅格之所以重要，是因为**生成器和 GUI 都按栅格取整**，不对齐就撞不上。
人手工画的线可以精确落在任意坐标上，所以：

→ **绝不要为了「对齐栅格」去自动挪人摆好的器件。** 挪 5 个单位，
   人画的线还停在原坐标，**一挪就断**。P4 实测：自动微调把 R41 从 175 推到 180，
   用户接的 CC2_N 当场脱开。**人摆的只报告，改不改由人决定。**
