## 1. 能做什么

### A. 看屏幕并直接分析波形 ✅ 已验证 ★核心能力

`:PRINt? PNG` 返回 **39 KB 裸 PNG**（无 IEEE 488.2 块头，比手册描述的简单）。存成文件后
我用 Read 工具直接看图。

**实测证据**：我已经读过一张你当前的屏幕截图，并从图中识别出——C2 上 24.0006 MHz 信号、
波形有明显过冲与振铃、20 ns/div、400 pts、2.00 GSa/s、触发 C2 DC 自动边沿上升 3.03 V、
C2 为 10X 探头 1.00 V/div 偏置 −1.57 V、测量栏显示 90-10% 下降时间 2.17 ns。

这条很重要，它意味着你可以直接问「看看现在波形什么样」「这个振铃正常吗」，
我看到的和你看到的是同一块屏幕。**这也是我主张不用 MCP 的实证**：MCP 返回 image block
与「CLI 存 PNG + Read」在模型侧完全等效。

### B. 读取仪器全部状态 ✅ 已验证

一次性抓完整配置快照，用于「现在是什么设置」「刚才改了什么」：

|---|---|---|

| 时基 | `:TIMebase:SCALe? DELay?` | `2.00E-08` `0.00E+00` |
| 触发 | `:TRIGger:` `STATus? TYPE? MODE?` `:EDGE:SOURce? LEVel? SLOPe?` | `Trig'd` `EDGE` `AUTO` `C2` `3.03E+00` `RISing` |
| 采集 | `:ACQuire:` `MODE? TYPE? MDEPth? SRATe? POINts? RESolution? STATe?` | `YT` `NORMal` `10M` `2.00E+09` `4.00E+02` `16Bits` `1` |
| 显示 | `:DISPlay:TYPE? GRID?` | `VECTor` `FULL` |

### C. 读取原始波形数据 ✅ 已验证

`:WAVeform:PREamble?` (346 字节二进制结构) + `:WAVeform:DATA?` (IEEE 488.2 块)。

**实测证据**：读到 400 点 16-bit 数据，解析 preamble 得
`vertical_gain=0.1  vertical_offset=-0.156667  code_per_div=7680  adc_bit=16  dt=5e-10s`，
换算出 2.00 GSa/s / 200 ns 时长，电压转换公式验证通过。

- 单次上限 `:WAVeform:MAXPoint? -> 5000000`（5 M 点）；存储深度 `:ACQuire:MDEPth? -> 10M`，
  读满需分段（`:WAVeform:STARt` + `:POINt`）。⚠️ 分段读取我**没实测**。
- 落地为 CSV/NPY 文件，**不进上下文**——10 M 点约 20 MB，塞进对话毫无意义。
  后续 FFT、找毛刺、比对两次采集，都在文件上用 numpy 做。

### D. 自动测量 ✅ 已验证（有前提）

`:MEASure:ADVanced:P<n>:TYPE?` / `:VALue?` 实测返回 `FALL90T10` / `2.23E-09`。

⚠️ **前提**：测量值的读取**依赖示波器当前的测量模式与已配置的测量槽位**。
当前机器是 `:MEASure:MODE? -> ADVanced`，此时 `:MEASure:SIMPle:VALue? PKPK` 返回
`'The number of measurements is zero'`——不是错误，是「你没配这个测量项」。
想测任意参数必须**先配置槽位**（写操作，见 §3）。

### E. 串行总线解码 ⚠️ 部分验证

`:DECode:BUS1:RESult?` 实测返回 `'i2c,address,data;'`——**解码功能在，且当前就配成 I2C 了**，
返回的是表头，说明还没捕获到数据。`:DECode:BUS1:FORMat? -> 'HEX'` 也通。

但 `:DECode:BUS1:SWITch?` `:TYPE?` `:STATe?` `:DISPlay?` **全部超时不支持**——我猜的命令名
是错的。要做这块必须查官方 Programming Guide 确认拼写，不能继续猜（见 §3 坑 4）。

这块对你调 I2C/SPI/UART 价值最大，但**我现在不能承诺**。

### F. 控制仪器（写操作）⚠️ 范围待你拍板

技术上全部可行（通道开关、档位、时基、触发电平、运行/停止、测量槽位配置、AUTOSET）。
**但这是需要你决定的事**，见 §4。

## 2. 明确不做

| | 原因 |
|---|---|
| ❌ 自动改被测电路相关的仪器设置 | 示波器可能正接在你在调的板子上，静默改档位/触发会让你看到的画面突变 |
| ❌ 固件升级、系统配置、网络设置 | 风险远大于收益 |
| ❌ 校准、自检 (`*CAL?`) | 耗时且会中断当前测量 |
| ❌ 把大波形数据塞进对话 | 落文件，用 numpy 分析 |
| ❌ 通过 Web (80 端口) 控制 | raw socket 更直接；Web 界面是给人用的 |

## 3. 已探明的坑（skill 的核心价值所在）

这 7 条全是实测撞出来的，**每一条都会让不知情的 AI 产出静默错误的结果**：

1. **两种 SCPI 语法并存，必须用标准语法。**
   `:CHANnel1:SCALe?` → `1.00E+00`（纯值）；`C1:VDIV?` → `C1:VDIV 1.00E+00V`（回显命令头
   + 带单位）。**Gemini 给你的是后者**。两种都能跑，但后者解析脏。

2. **探头倍率陷阱 —— 最危险的一条。**
   `:CHANnel2:SCALe?` = `1.00E+00`（**含** 10X 探头），但 preamble 的
   `vertical_gain` = `0.1`（**不含**）。比值正好等于 `:CHANnel2:PROBe?` = `10`。
   直接用 preamble 算电压会**小 10 倍，而且不报任何错**。

3. **HD 机型默认按 8-bit 传波形。**
   `:WAVeform:WIDTh?` 默认 `BYTE`。你买的是 HD（高分辨率）机器，不设 `WORD` 就白瞎了
   ADC 精度。实测设 `WORD` 后 400 点返回 800 字节，确认生效。

4. **不支持的命令静默超时 3 秒，不立即报错。**
   实测 `:DECode:BUS1:SWITch?` 等十余条全部 timeout 无响应。AI 瞎猜命令名会反复卡死。
   **必须以官方 Programming Guide 为准，不要猜拼写。**

5. **错误队列是 FIFO、严重滞后、而且会溢出。**
   实测一轮探测后 `:SYSTem:ERRor?` 连弹 6 条，弹出来的还是**上一轮**的错误
   （`-113,"Undefined header;:DECode:BUS1:TYPE?"`）。继续排空到第 10 条时拿到
   `-350,"Queue overflow"`——**队列深度有限（实测约 16 条），溢出后早期错误被直接丢弃**。
   所以：排查前必须先循环排空队列到 `0,"No error"`，且**每条写操作后立刻查**，
   不要攒一批再查——攒多了真正的错误可能已经被挤掉了。

6. **测量查询依赖当前测量模式。** 见 §1-D。返回
   `'The number of measurements is zero'` 时不是通信失败，是没配测量项。

7. **`:PRINt?` 必须带参数。** `:PRINt? PNG` 正常，裸 `:PRINt?` 超时。

## 4. 需要你拍板：写操作开到什么程度

这是唯一的真分歧点。示波器大概率正接在你在调的板子上，静默改设置会让你看到的画面突变。
三个档位：

| 档位 | 范围 | 代价 |
|---|---|---|
| **A. 纯只读** | 只查询、截图、读波形。任何改设置都让你自己动手 | 最安全，但「帮我把时基调到看清一个周期」做不了 |
| **B. 只读 + 改前确认**（我的建议） | 写操作前把「要改什么、当前值、改后值」列给你，你点头才发 | 多一次往返，但不会有意外 |
| **C. 放开常用写操作** | 通道/时基/触发/测量槽位直接改，只有 AUTOSET、复位、保存需确认 | 流畅，但你盯着屏幕调试时可能被突然改掉 |

无论哪档，这三条我都会写进 SKILL.md 作为硬约束：
- **每次写操作后立即查 `:SYSTem:ERRor?`**，确认命令被接受而不是被静默丢弃
- **改之前先存原值**，报告里带上，方便你让我改回去
- **绝不碰** `*RST`、校准、固件、网络配置

## 5. 提议的 CLI 边界

```
software/siglent-scope/
├── SKILL.md
└── scripts/
    └── scope.py        # 仅依赖 Python 标准库 socket
```

```bash
scope.py idn                        # 连通性 + 身份自检
scope.py state                      # 一次抓全配置快照（§1-B 那张表）
scope.py shot out.png               # 截图 → 我 Read 看图分析
scope.py wave C2 out.csv            # 读波形（自动设 WORD、自动乘探头倍率）
scope.py meas                       # 列当前已配置的测量槽位及值
scope.py errors                     # 循环排空错误队列 ← 排查第一步
scope.py q ":CHANnel1:SCALe?"       # 任意查询逃生口
scope.py w ":TIMebase:SCALe 1E-6"   # 任意写入（按 §4 档位决定是否要确认）
```

`wave` 子命令会把坑 2、3 封死在脚本里（自动 `WORD`、自动乘 `:PROBe?`），
这样「忘了乘探头倍率」这种静默错误**在工具层就不可能发生**，而不是指望 AI 每次记得。
